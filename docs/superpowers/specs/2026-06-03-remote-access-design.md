# Remote Access Design — SprinKlr-8

**Date:** 2026-06-03  
**Version target:** v1.8.0  
**Branch:** custom-board

---

## Overview

Three independent features that together make the controller fully accessible from anywhere:

1. **Tailscale** — subnet routing on Windows PC, full web UI access from phone
2. **PWA** — web UI installable as a native-feeling app on phone homescreen
3. **Telegram Bot** — notifications + basic commands from anywhere

All three are independent. Tailscale has zero firmware changes. PWA is UI-only. Telegram adds a firmware task and Settings UI. Each can be shipped and used without the others.

---

## 1. Tailscale (Setup Only — No Code Changes)

### How It Works
The ESP32 cannot run a Tailscale client. A Windows PC on the home network acts as a **subnet router**: it advertises the home subnet to Tailscale, so any Tailscale-connected device can route traffic through it to reach the ESP32.

### Setup Steps
1. Install Tailscale on the Windows home PC. Enable "Run at startup."
2. In Tailscale settings on the PC, enable **subnet routing** and advertise `10.110.201.0/24`.
3. In the Tailscale admin console (web), approve the advertised subnet.
4. Install Tailscale on the phone. Log into the same account.
5. Done — board accessible at `http://10.110.201.40` from anywhere.

### Properties
- **Local access:** unchanged — `http://sprinkler.local` and `http://10.110.201.40` still work on the home network
- **Encryption:** WireGuard end-to-end. Tailscale servers broker connections but do not relay traffic.
- **Authentication:** Tailscale account login. Only devices on your account can access the network.
- **Cost:** Free for personal use
- **Privacy:** High — Tailscale sees metadata (device names, IPs), not traffic content

## 2. PWA (UI + Firmware Routes)

### Goal
Make the existing web UI installable on the phone homescreen with a native app feel — correct icon, app name, no browser chrome, themed status bar.

### New Files (in `data/`, served from LittleFS)

| File | Purpose |
|------|---------|
| `manifest.json` | PWA manifest — name, icons, display mode, theme color |
| `sw.js` | Minimal service worker — makes the app installable; shows offline page if board unreachable |
| `icon-192.png` | Home screen icon (192×192) |
| `icon-512.png` | Splash / store icon (512×512) |

Icons are a teal water-drop design generated by a Python script (`tools/gen_icons.py`).

### `manifest.json` Content
```json
{
  "name": "SprinKlr",
  "short_name": "SprinKlr",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#0f172a",
  "theme_color": "#0d9488",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
```

### `sw.js` Behavior
- Registers a service worker with a minimal install handler
- Caches the offline fallback page only (board must be reachable for full functionality)
- No aggressive caching — board is the source of truth for all data

### Changes to `index.html`
```html
<!-- In <head> -->
<link rel="manifest" href="/manifest.json">
<meta name="theme-color" content="#0d9488">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">
<meta name="apple-mobile-web-app-title" content="SprinKlr">
<link rel="apple-touch-icon" href="/icon-192.png">

<!-- Before </body> -->
<script>
  if ('serviceWorker' in navigator) {
    navigator.serviceWorker.register('/sw.js');
  }
</script>
```

### New Firmware Routes
```cpp
GET /manifest.json  → streamFile from LittleFS, MIME: application/manifest+json
GET /sw.js          → streamFile from LittleFS, MIME: application/javascript
GET /icon-192.png   → streamFile from LittleFS, MIME: image/png
GET /icon-512.png   → streamFile from LittleFS, MIME: image/png
```

### Install Experience
- **Android (Chrome):** "Add to Home Screen" prompt appears automatically after a few visits. Also available via browser menu.
- **iOS (Safari):** User taps Share → "Add to Home Screen." No automatic prompt on iOS.
- Once installed: opens full-screen, teal status bar, SprinKlr icon, no browser URL bar.

## 3. Telegram Bot (Firmware + UI)

### Architecture
The ESP32 runs a FreeRTOS task (`telegramTask`) that long-polls the Telegram Bot API. The board is the bot — it polls for incoming messages and sends outbound notifications. No relay server required.

### Config Fields Added to `BoardConfig`
```cpp
bool telegramEnabled;           // master on/off
char telegramToken[128];        // bot token from @BotFather
char telegramChatId[32];        // your personal chat ID (security: ignore all others)
```

Config JSON keys: `telegram_enabled`, `telegram_token`, `telegram_chat_id`.

### `telegramTask()` — FreeRTOS Task
- Runs when `telegramEnabled == true` and WiFi is connected
- Long-polls: `GET https://api.telegram.org/bot{token}/getUpdates?timeout=25&offset={offset}`
- On each message: checks `chat_id` matches config — ignores all others
- Parses command text, dispatches to handler
- Tracks `lastUpdateId` to avoid reprocessing (persisted in RAM, reset on reboot)
- Stack size: 6144 bytes

### `telegramSend(const char* msg)` — Helper
- Non-blocking POST to `sendMessage` endpoint
- Called from existing notification callpoints
- Creates a short-lived `HTTPClient`, sends, closes
- If `telegramEnabled == false` or WiFi disconnected: returns immediately (no-op)

### Commands
| Command | Response |
|---------|---------|
| `/status` | Current temp, weather condition, next scheduled run time |
| `/run <zone> <min>` | Starts zone (1-indexed). E.g. `/run 3 10` runs Zone 3 for 10 min. Responds with confirmation. |
| `/skip` | Skips today's scheduled run. Responds with confirmation. |
| `/stop` | Stops current run immediately. |
| `/help` | Lists all commands. |

Invalid zone numbers or missing args get a helpful error response.

### Automatic Notifications
Sent by calling `telegramSend()` at the same callpoints as `appendRunLog()`:

| Event | Message |
|-------|---------|
| Run started (scheduled) | "💧 Scheduled run started — 4 zones, ~22 min" |
| Run started (manual) | "💧 Manual run started — Zone 3, 10 min" |
| Run completed | "✅ Run complete — Zone 1 (10m), Zone 2 (8m), Zone 3 (5m). Total: 23 min." |
| Weather skip | "⏭ Run skipped — Rain 85% (threshold 50%)" |
| Freeze skip | "⏭ Run skipped — Freeze warning 30°F (threshold 35°F)" |

### Settings UI
New "Telegram" subsection in the Settings tab:

- **Enable Telegram** toggle
- **Bot Token** text field (password type, obscured)
- **Chat ID** text field
- **Send Test Message** button — sends "SprinKlr connected ✅" to verify config
- Setup instructions inline: link to @BotFather, how to get chat ID via @userinfobot

### Security
- Only messages from the configured `chat_id` are processed. All others silently ignored.
- Token stored in `config.json` on LittleFS (same security level as WiFi credentials).
- Commands that start zones or skip runs are only accepted from the authorized chat ID.

## Scope Boundaries

**Not in this version:**
- Push notifications via Web Push API (requires third-party infrastructure)
- SMTP email notifications (separate feature, planned separately)
- HomeKit / Alexa / Google Home integration
- Native iOS/Android app
- Telegram group chat support (single chat ID only)
